# Шифрование системного диска Ubuntu (LUKS2) без переустановки

Гайд описывает, как зашифровать уже установленную Ubuntu «на месте»: данные остаются на диске, а раздел с корнем превращается в LUKS2-контейнер. Переустанавливать систему не нужно.

Проверено на Ubuntu 26.04 LTS, cryptsetup 2.8, UEFI, ext4 на NVMe. На других версиях Ubuntu и Debian шаги те же, но имена пакетов и пунктов меню могут отличаться.

> **Внимание.** Процесс переписывает весь раздел. Сбой питания, ошибка в имени устройства или забытый пароль могут стоить всех данных. **Не начинайте без проверенной резервной копии на другом физическом диске.**

## 1. Когда подходит этот гайд

Исходная разметка, под которую написан гайд:

```
nvme0n1
├─nvme0n1p1  vfat  /boot/efi   (EFI-раздел)
└─nvme0n1p2  ext4  /           (корень, /boot внутри него)
```

Результат после шифрования:

```
nvme0n1
├─nvme0n1p1      vfat         /boot/efi   (без изменений)
├─nvme0n1p2      crypto_LUKS              (зашифрованный контейнер)
│ └─cryptroot    ext4         /           (та же файловая система, что была)
└─nvme0n1p3      ext4         /boot       (новый, незашифрованный)
```

Отдельный незашифрованный `/boot` нужен потому, что GRUB плохо работает с LUKS2 (в частности, не поддерживает Argon2). Если оставить `/boot` внутри зашифрованного раздела, система не загрузится. Стандартный установщик Ubuntu делает такую же разметку.

Если у вас другая разметка (LVM, Btrfs, отдельный `/home`, dual boot с Windows), гайд нужно адаптировать. Проще и безопаснее в таком случае переустановить систему с опцией шифрования в установщике.

## 2. Риски

| Риск | Последствие | Как снизить |
|---|---|---|
| Забыт пароль LUKS | Данные потеряны навсегда, восстановить невозможно | Записать пароль в менеджер паролей и на бумагу; добавить второй пароль (раздел 11) |
| Отключение питания во время шифрования | Процесс прерван, раздел в промежуточном состоянии | Работать от сети, по возможности через ИБП; продолжить через `--resume-only` (раздел 12) |
| Аппаратный сбой SSD | Повреждение данных | Заранее проверить SMART (раздел 4) |
| Перепутано устройство (`/dev/sdX` вместо `/dev/nvme0n1pX`) | Уничтожен не тот диск | Каждый раз сверяться с `lsblk -f`; отключить лишние диски |
| Повреждён заголовок LUKS | Раздел не открывается даже с верным паролем | Сохранить копию заголовка (раздел 11) |
| Ошибка в настройке загрузки | Система не загружается, данные целы | Исправляется с live-USB (раздел 12) |

Шифрование защищает данные, когда компьютер выключен: при краже, потере или сдаче в ремонт. От вирусов и удалённого доступа к уже включённой системе оно не защищает.

## 3. Что понадобится

- **Внешний диск** с объёмом больше, чем занято на системном, для резервной копии.
- **Флешка с Ubuntu** той же версии, что установлена (8 ГБ и больше). Записывается через `Startup Disk Creator`, `balenaEtcher` или `dd`.
- **Парольная фраза** для LUKS: 4–6 случайных слов или 20+ символов. Записать её **до** начала.
- **Питание:** ноутбук подключён к сети, желательно через ИБП.
- **Время:** 1–3 часа. Само шифрование NVMe на 500 ГБ занимает от 30 минут до пары часов.
- **Свободное место:** около 2,5 ГБ в конце диска под новый `/boot` (освобождается за счёт уменьшения корня).

## 4. Проверка системы

Все команды в этом разделе только читают данные.

**Разметка диска:**

```bash
lsblk -f -e 7
```

Убедитесь, что разметка совпадает с разделом 1: EFI-раздел и один ext4-раздел с корнем, без `crypto_LUKS`, LVM или Btrfs.

**Режим загрузки** (должен быть UEFI):

```bash
[ -d /sys/firmware/efi ] && echo UEFI || echo BIOS
```

**Здоровье SSD:**

```bash
sudo apt install -y smartmontools
sudo smartctl -a /dev/nvme0n1
```

Смотрите на строки:

| Параметр | Норма |
|---|---|
| `SMART overall-health` | `PASSED` |
| `Critical Warning` | `0x00` |
| `Media and Data Integrity Errors` | `0` |
| `Available Spare` | заметно выше `Available Spare Threshold` |
| `Percentage Used` | далеко от 100% |
| `Unsafe Shutdowns` | чем меньше, тем лучше; большое число говорит о частых отключениях питания, тогда особенно важен ИБП |

Если есть ошибки носителя или критические предупреждения, сначала сделайте резервную копию и замените диск, шифровать его не стоит.

**Ошибки ядра по диску:**

```bash
sudo dmesg | grep -iE "nvme|i/o error|ext4" | tail -n 50
```

Повторяющиеся `I/O error` или `nvme ... reset` означают проблемы с диском.

## 5. Резервная копия

Этот раздел обязателен. Без копии на **другом физическом диске** дальше не идите.

### 5.1. Подключить внешний диск

Если внешний диск сам зашифрован LUKS, откройте его:

```bash
lsblk -f                       # найти внешний диск, например /dev/sda с FSTYPE crypto_LUKS
sudo cryptsetup open /dev/sda backup
sudo mkdir -p /mnt/backup
sudo mount /dev/mapper/backup /mnt/backup
```

Если открываете файлом-ключом, добавьте `--key-file /полный/путь/к/ключу`. Путь указывайте от корня, без `~`.

Если рабочий стол сам открыл и смонтировал диск (обычно в `/run/media/<пользователь>/<UUID>` или `/media/<пользователь>/<метка>`), используйте этот путь вместо `/mnt/backup`.

**Обязательно проверьте, что диск действительно смонтирован:**

```bash
findmnt /mnt/backup
df -h /mnt/backup
```

`findmnt` должен вывести строку с `/dev/mapper/...` или `/dev/sdX`. Если вывод пустой, диск **не** смонтирован, и копия попадёт на системный диск, то есть окажется бесполезной.

### 5.2. Скопировать данные

```bash
DEST=/mnt/backup/backup-$(date +%F)

findmnt /mnt/backup && sudo mkdir -p "$DEST" && cd "$DEST" && \
sudo rsync -aHAX --info=progress2 \
  --exclude='.cache/' --exclude='.local/share/Trash/' \
  /home/ ./home/ && \
sudo rsync -aHAX /etc/ ./etc/ && \
sudo rsync -aHAX /usr/local/ ./usr-local/ && \
sudo rsync -aHAX /opt/ ./opt/ && \
apt-mark showmanual | sudo tee packages-manual.txt >/dev/null && \
snap list | sudo tee snaps.txt >/dev/null && \
{ crontab -l 2>/dev/null | sudo tee crontab.txt >/dev/null; true; }
```

Команды соединены через `&&`: если диск не смонтирован или шаг завершился ошибкой, следующие не выполнятся.

Если у вас есть данные вне `/home`, `/etc`, `/usr/local` и `/opt` (например, `/srv`, `/var/lib/docker`, базы данных), добавьте их отдельными строками `rsync`.

### 5.3. Проверить копию

```bash
sudo rsync -aHAXn --checksum \
  --exclude='.cache/' --exclude='.local/share/Trash/' \
  /home/ "$DEST/home/" | tail -n 20
```

Флаг `-n` означает пробный прогон: ничего не копируется, только выводятся отличия. Пустой вывод или только недавно изменённые файлы (браузер, мессенджеры) означают, что копия совпадает.

Дополнительно:

- откройте несколько важных файлов прямо с внешнего диска;
- проверьте, что в копии есть `.ssh`, `.gnupg` и база менеджера паролей, если он локальный.

### 5.4. Отключить внешний диск

```bash
cd ~
sudo umount /mnt/backup
sudo cryptsetup close backup
```

Физически отключите диск. Во время шифрования он должен быть отсоединён, чтобы его нельзя было случайно задеть.

## 6. Подготовка в работающей системе

Без этого пакета initramfs не сможет спросить пароль при загрузке:

```bash
sudo apt update
sudo apt install -y cryptsetup cryptsetup-initramfs
```

Запишите текущую разметку на случай, если понадобится восстановление:

```bash
sudo sfdisk -d /dev/nvme0n1 > ~/partition-table-backup.txt
lsblk -f -e 7 > ~/lsblk-before.txt
```

Скопируйте эти два файла на внешний диск или в облако: после шифрования они будут внутри зашифрованного раздела.

## 7. Расчёт новой разметки

Нужно освободить место в конце диска под новый `/boot` (около 2,3 ГиБ) и оставить место под заголовок LUKS (32 МиБ).

Посмотрите текущую разметку в мебибайтах:

```bash
sudo parted /dev/nvme0n1 unit MiB print
```

Пример вывода для диска 512 ГБ:

```
Disk /dev/nvme0n1: 488386MiB
Number  Start    End        Size       File system  Name
 1      1.00MiB  1076MiB    1075MiB    fat32
 2      1076MiB  488385MiB  487309MiB  ext4
```

Рассчитайте три числа:

| Величина | Формула | Пример |
|---|---|---|
| `BOOT_START` — начало нового `/boot` | размер диска − ~2400 МиБ, округлить вниз | 488386 − 2386 = **486000** МиБ |
| `ROOT_SIZE` — новый размер раздела p2 | `BOOT_START` − `Start` раздела 2 | 486000 − 1076 = 484924 МиБ |
| `FS_SIZE` — новый размер ext4 | меньше `ROOT_SIZE` − 32 МиБ, с запасом | **470G** (481280 МиБ) |

Запас между `FS_SIZE` и `ROOT_SIZE` нужен для заголовка LUKS. В конце файловая система снова растянется на всё доступное место, так что запас ничего не стоит.

`FS_SIZE` должен быть **больше**, чем сейчас занято на корне (`df -h /`, колонка `Used`), с запасом хотя бы в 10%.

## 8. Шифрование с live-USB

Корень нельзя шифровать, пока с него работает система. Все шаги ниже выполняются с флешки.

1. Убедитесь, что внешний диск с бэкапом **отключён**.
2. Подключите ноутбук к сети.
3. Загрузитесь с флешки (обычно `F12`, `F2` или `Esc` при включении), выберите «Попробовать Ubuntu».
4. Откройте терминал и станьте root:

```bash
sudo -i
```

5. Задайте переменные. **Сверьте их с `lsblk -f`**, имена у вас могут отличаться:

```bash
lsblk -f -e 7

DISK=/dev/nvme0n1
EFI=${DISK}p1
ROOT=${DISK}p2
BOOT=${DISK}p3
BOOT_START=486000   # из раздела 7
FS_SIZE=470G        # из раздела 7
```

Для SATA-дисков (`/dev/sda`) номера разделов пишутся без `p`: `/dev/sda1`, `/dev/sda2`.

### 8.1. Уменьшить файловую систему и раздел

```bash
e2fsck -f "$ROOT"
resize2fs "$ROOT" "$FS_SIZE"
parted "$DISK" unit MiB resizepart 2 "$BOOT_START"
parted "$DISK" mkpart boot ext4 "${BOOT_START}MiB" 100%
mkfs.ext4 -L boot "$BOOT"
```

`parted` предупредит, что уменьшение раздела может привести к потере данных. Отвечайте `Yes`: файловая система уже уменьшена и помещается в новый размер.

Проверьте результат:

```bash
lsblk -f "$DISK"
```

Должны быть три раздела: p1 (vfat), p2 (ext4), p3 (ext4, метка `boot`).

### 8.2. Перенести /boot на новый раздел

```bash
mkdir -p /mnt/root /mnt/newboot
mount "$ROOT" /mnt/root
mount "$BOOT" /mnt/newboot
cp -a /mnt/root/boot/. /mnt/newboot/
ls /mnt/newboot                 # должны быть vmlinuz-*, initrd.img-*, grub/
umount /mnt/root /mnt/newboot
```

Старые файлы `/boot` внутри корня останутся. Они будут скрыты новым разделом, смонтированным поверх, и ничему не помешают.

### 8.3. Зашифровать раздел

```bash
cryptsetup reencrypt --encrypt --type luks2 --reduce-device-size 32M "$ROOT"
```

- На вопрос `Are you sure? (Type 'yes' in capital letters)` введите `YES`.
- Дважды введите парольную фразу.
- Дождитесь окончания. Прогресс показывается в процентах.

`--reduce-device-size 32M` берёт последние 32 МиБ раздела под заголовок LUKS. Именно для этого в разделе 7 файловая система уменьшалась с запасом.

**Если процесс прервался** (сбой питания, зависание), ничего не форматируйте. Загрузитесь с флешки и продолжите:

```bash
cryptsetup reencrypt --resume-only /dev/nvme0n1p2
```

### 8.4. Растянуть файловую систему

```bash
cryptsetup open "$ROOT" cryptroot
e2fsck -f /dev/mapper/cryptroot
resize2fs /dev/mapper/cryptroot
```

## 9. Настройка загрузки

Войдите в установленную систему через `chroot`:

```bash
mount /dev/mapper/cryptroot /mnt
mount "$BOOT" /mnt/boot
mount "$EFI" /mnt/boot/efi
for d in dev proc sys run; do mount --rbind /$d /mnt/$d; done
chroot /mnt /bin/bash
```

Переменные из раздела 8 внутри `chroot` не видны, поэтому ниже устройства указаны явно. Если у вас другие имена, замените их.

### 9.1. crypttab

```bash
echo "cryptroot UUID=$(blkid -s UUID -o value /dev/nvme0n1p2) none luks,discard" >> /etc/crypttab
cat /etc/crypttab
```

`discard` включает TRIM для SSD: это полезно для скорости и ресурса. Цена в том, что снаружи видно, какие блоки свободны, но не их содержимое. Если для вас это важно, уберите `,discard`.

### 9.2. fstab

```bash
echo "UUID=$(blkid -s UUID -o value /dev/nvme0n1p3) /boot ext4 defaults 0 2" >> /etc/fstab
cat /etc/fstab
```

Строку для `/` менять **не нужно**: UUID файловой системы ext4 внутри LUKS остался прежним.

### 9.3. initramfs и GRUB

```bash
update-initramfs -u -k all
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=ubuntu
update-grub
```

Проверьте, что в initramfs попал cryptsetup:

```bash
lsinitramfs "$(ls /boot/initrd.img-* | sort -V | tail -n 1)" | grep -m3 cryptsetup
```

Если вывод пустой, пакет `cryptsetup-initramfs` не установлен. Установите его (`apt install cryptsetup-initramfs`, нужен интернет в live-сессии) и повторите `update-initramfs -u -k all`.

### 9.4. Выйти и перезагрузиться

```bash
exit
umount -R /mnt
cryptsetup close cryptroot
reboot
```

Извлеките флешку, когда система попросит.

## 10. Первая загрузка и проверка

При загрузке появится запрос парольной фразы. После входа проверьте:

```bash
lsblk -f -e 7
```

Ожидаемый результат:

```
nvme0n1
├─nvme0n1p1    vfat         /boot/efi
├─nvme0n1p2    crypto_LUKS
│ └─cryptroot  ext4         /
└─nvme0n1p3    ext4         /boot
```

```bash
sudo cryptsetup status cryptroot
df -h / /boot
```

`cryptsetup status` должен показать `type: LUKS2` и `cipher: aes-xts-plain64`.

## 11. После шифрования

### Копия заголовка LUKS

Без заголовка раздел не открыть даже с правильным паролем. Сохраните его копию **вне** зашифрованного диска (внешний диск, облако):

```bash
sudo cryptsetup luksHeaderBackup /dev/nvme0n1p2 --header-backup-file /mnt/backup/luks-header-nvme0n1p2.img
```

Восстановление при необходимости:

```bash
sudo cryptsetup luksHeaderRestore /dev/nvme0n1p2 --header-backup-file /путь/к/luks-header-nvme0n1p2.img
```

Копия заголовка вместе со старым паролем открывает диск, даже если пароль потом поменяли. Храните её так же надёжно, как сам пароль.

### Второй пароль (запасной ключ)

LUKS позволяет иметь несколько паролей. Добавьте длинный запасной и храните его отдельно (например, на бумаге в надёжном месте):

```bash
sudo cryptsetup luksAddKey /dev/nvme0n1p2
sudo cryptsetup luksDump /dev/nvme0n1p2 | grep -A1 Keyslots
```

### Смена пароля

```bash
sudo cryptsetup luksChangeKey /dev/nvme0n1p2
```

### Ядро и обновления

Обновления ядра и GRUB работают как обычно: `update-initramfs` и `update-grub` вызываются автоматически. Отдельно ничего делать не нужно.

## 12. Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| `Device ... is not a valid LUKS device` при `cryptsetup open` | Раздел ещё не зашифрован или указан не тот раздел | Проверить `lsblk -f`: у нужного раздела должен быть `FSTYPE crypto_LUKS` |
| `resize2fs: New size smaller than minimum` | Слишком маленький `FS_SIZE` | Увеличить `FS_SIZE` (раздел 7) или освободить место |
| Шифрование прервалось | Сбой питания или зависание | Загрузиться с флешки, `cryptsetup reencrypt --resume-only /dev/nvme0n1p2` |
| После перезагрузки — `grub rescue>` или `grub>` | GRUB не нашёл `/boot` | Live-USB → шаги 8.4 и 9 (`chroot`, `grub-install`, `update-grub`) |
| Нет запроса пароля, система падает в `(initramfs)` | Нет `cryptsetup-initramfs` или ошибка в `/etc/crypttab` | Live-USB → `chroot` (раздел 9) → проверить `/etc/crypttab`, установить пакет, `update-initramfs -u -k all` |
| `cryptsetup: ERROR: cryptroot: Source mismatch` или ожидание устройства | Неверный UUID в `/etc/crypttab` | Сравнить с `blkid /dev/nvme0n1p2` |
| Пароль не принимается | Раскладка клавиатуры при загрузке (часто вводится в английской) | Попробовать ввести пароль, как если бы раскладка была английской; в будущем лучше использовать пароль из латиницы |
| Повреждён заголовок | Сбой диска или ошибочная команда | `luksHeaderRestore` из копии (раздел 11) |
| Забыт пароль, нет запасного ключа и копии заголовка со старым паролем | — | Данные не восстановить; переустановка и восстановление из бэкапа |

### Ручное открытие с live-USB

Пригодится для любых исправлений:

```bash
sudo -i
cryptsetup open /dev/nvme0n1p2 cryptroot
mount /dev/mapper/cryptroot /mnt
mount /dev/nvme0n1p3 /mnt/boot
mount /dev/nvme0n1p1 /mnt/boot/efi
for d in dev proc sys run; do mount --rbind /$d /mnt/$d; done
chroot /mnt /bin/bash
```

После исправлений:

```bash
exit
umount -R /mnt
cryptsetup close cryptroot
reboot
```

### Откат

Самый надёжный способ вернуться к незашифрованной системе — переустановить Ubuntu и восстановить данные из резервной копии (раздел 5).
